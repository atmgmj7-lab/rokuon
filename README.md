# Rokuon - 録音アプリケーション

Next.js 14+ (App Router)、TypeScript、Tailwind CSS、Turso を使用した録音アプリケーションです。

## セットアップ

### 1. 依存関係のインストール

```bash
npm install
```

### 2. 環境変数の設定

`.env` ファイルに以下の環境変数を設定してください：

```env
TURSO_DATABASE_URL=libsql://your-database.turso.io
TURSO_AUTH_TOKEN=your-auth-token
OPENAI_API_KEY=sk-your-openai-api-key
GOOGLE_AI_API_KEY=your-google-ai-api-key
```

#### Tursoデータベースの作成方法

1. [Turso](https://turso.tech/) にアカウントを作成
2. Turso CLIをインストール:
   ```bash
   brew install tursodatabase/tap/turso
   ```
3. ログイン:
   ```bash
   turso auth login
   ```
4. データベースを作成:
   ```bash
   turso db create rokuon
   ```
5. データベースURLを取得:
   ```bash
   turso db show rokuon --url
   ```
6. 認証トークンを取得:
   ```bash
   turso db tokens create rokuon
   ```

### 3. データベースマイグレーション

環境変数を設定した後、以下のコマンドでデータベーステーブルを作成します：

```bash
npm run migrate
```

### 4. 開発サーバーの起動

```bash
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開いてください。

## 機能

### 🎙️ Phase 1: テレアポ音声アップロード & 文字起こし

1. ホームページにアクセスすると、音声アップロードフォームが表示されます
2. タイトルと説明（任意）を入力し、音声ファイルを選択します
3. 「📤 アップロードして文字起こし」ボタンをクリックします
4. OpenAI Whisper APIが音声を解析し、自動的に文字起こしを行います（数十秒かかります）
5. 文字起こし結果がその場で表示され、データベースに保存されます

**特徴:**
- テレアポに最適化されたプロンプト（フィラー「えー、あのー」を残して正確に書き起こし）
- リアルタイムのローディング状態表示
- ファイルサイズ、録音時間などのメタデータも自動保存
- Tursoデータベースに安全に保存

### 📞 Phase 2: インタラクティブなトークスクリプト（Talkz風UI）

アポインターが通話中に画面を見ながら、顧客の反応に合わせてトークを分岐させる機能。

1. ホームページから「📞 トークスクリプト」をクリック
2. スクリプト一覧ページで「➕ 新規スクリプトを作成」
3. サンプルスクリプトを作成して実行
4. 通話中に顧客の反応に応じて選択肢をクリック
5. 自動的に次のトークが表示される

**特徴:**
- 分岐型トークスクリプト（顧客の反応に応じて自動分岐）
- 会話履歴の表示（どの経路を辿ったか確認可能）
- 戻る機能（前の選択に戻れる）
- リセット機能（最初からやり直せる）
- サンプルスクリプト付き（CRM営業のトークフロー）
- Talkz風の洗練されたUI

**使い方:**
1. 通話前にスクリプトを開く
2. 通話しながら画面を見てトークを読む
3. 顧客の反応に応じて選択肢をタップ
4. 次に言うべきことが自動表示される

### 📊 実行ログ機能（自動保存）

スクリプトの実行履歴を自動的にデータベースに保存し、分析できる機能。

**自動記録される情報:**
- どのルートを通ったか（ノードIDの配列）
- 最終的な結果（アポ獲得、断られた、資料送付など）
- 実行日時

**ログの閲覧:**
1. スクリプト一覧で「📊」ボタンをクリック
2. 実行ログページで統計情報を確認
   - 総実行回数
   - アポ獲得数
   - 断られた数
3. 各実行の詳細な分岐ルートを確認

**活用方法:**
- どの分岐パターンが成約につながりやすいかを分析
- 断られやすいポイントを特定してスクリプトを改善
- チーム全体のトーク品質を可視化

### 🤖 Phase 3: 音声・指導ペアのマルチモーダル分析（Gemini 1.5 Pro）

「誰でもトップアポインターになれる」ための核心機能。課題音声と指導音声をペアで分析し、再現可能なノウハウを抽出。

**機能:**
1. **課題音声のアップロード**
   - 新人のテレアポ音声をアップロード
   - 自動的にWhisperで文字起こし

2. **指導音声の紐付け**
   - 課題音声に対して、マネージャーの指導音声を追加
   - 親子関係でデータベースに保存
   - 指導音声も自動で文字起こし

3. **AI分析（Gemini 1.5 Pro）**
   - 課題音声と指導音声を比較分析
   - 上司が指摘している「正解の論理」を抽出
   - 業種・状況タグを自動付与
   - 学習用ナレッジとして構造化

**分析結果に含まれる情報:**
- 📊 分析サマリー
- ❌ 問題点（新人の課題）
- ✅ 正解アプローチ（上司の指摘）
- 🧠 理由・根拠（なぜそれが正解か）
- 🏷️ タグ（業種、顧客反応、トークフェーズ）
- 💡 学習用ナレッジ（再現可能なノウハウ）
- 📝 スクリプト提案（次回のトーク改善案）

**使い方:**
1. 「📼 録音一覧」から課題音声を確認
2. 「➕ 指導音声を追加」をクリック
3. マネージャーの指導音声をアップロード
4. 「🤖 AI分析」ボタンでGeminiが自動分析
5. 抽出されたナレッジを今後のトレーニングに活用

### 🎨 Phase 4: ビジュアル・スクリプト・エディタと思考同期型カンペUI

トップアポインターの「思考のツリー」を可視化し、顧客属性に応じて動的にトークを出し分ける革新的なシステム。

#### 1. ビジュアル・スクリプト・エディタ

**ReactFlowを使用したドラッグ&ドロップエディタ:**
- 📊 スクリプトの分岐構造を視覚的に編集
- 🔗 ノード同士をドラッグで接続
- 📝 各ノードの詳細をサイドパネルで確認・編集
- 💾 変更をワンクリックで保存
- 🗺️ ミニマップで全体構造を把握

**使い方:**
1. スクリプト一覧で「✏️」ボタンをクリック
2. ビジュアルエディタでノードを配置
3. ノードをクリックして詳細を確認
4. 「💾 保存」で変更を反映

#### 2. 思考同期型 Live Assistant

**プレ・コール調査システム:**

通話前に顧客の属性を選択すると、最適なトークが自動的に表示される革新的なUI。

**属性タグ:**
- 🌐 **Web状況**: HPなし / SNSのみ / 広告あり
- 👔 **求人状況**: 募集中 / なし
- 🎯 **ターゲット**: 社長 / 担当者

**仕組み:**
1. 各開始ノードに `hypothesis_tags` を設定
2. アポインターがタグを選択
3. AIがマッチングスコアを計算
4. 最適なスタートノードを自動選択
5. そのノードから通話を開始

**使い方:**
1. スクリプト一覧で「🎯 Live Assistant」をクリック
2. プレ・コール調査パネルで顧客属性を選択
3. 最適なトークが自動的にハイライト
4. 「📞 このトークで通話を開始」をクリック

#### 3. AI提案の承認・反映フロー

**分析結果からスクリプトへの自動提案:**

Gemini分析で抽出された「新しい切り返し案」を、ワンクリックでスクリプトに追加。

**フロー:**
1. 📊 AI分析を実行
2. 🤖 「新しい切り返し案」を提案として生成
3. ✏️ スクリプト編集ページの「AI提案」タブで確認
4. ✅ 「承認して追加」でビジュアルエディタに反映
5. 🎨 エディタで位置を調整して保存

**特徴:**
- 分析結果を手動で転記する必要なし
- 提案内容を詳細に確認してから承認
- 却下した提案は記録されない
- 人間の判断を尊重した半自動化

## データベーススキーマ

### recordings テーブル
- 録音データのメタデータを保存
- `recording_type`: 'case' (課題音声), 'model' (お手本), 'feedback' (指導音声)
- `parent_id`: 指導音声の場合、課題音声のIDを参照
- `category_id`: 業種・属性等の区分

### users テーブル
- ユーザー情報を保存（将来的な拡張用）

### transcripts テーブル
- 録音の文字起こしデータを保存

### scripts テーブル
- トークスクリプトと分岐ロジックをJSON形式で保存

### script_logs テーブル
- スクリプト実行ログ（通過した分岐ルート、結果ステータス）を保存

### analysis_results テーブル
- Gemini 1.5 Proによる分析結果を保存
- 課題音声と指導音声のペア分析
- 抽出されたタグ、学習用ナレッジ

### knowledge_base テーブル
- 静的なトーク集・戦略メモ
- カテゴリ、ロジック説明、成功要因、次の一手

### script_categories テーブル
- 階層構造の大カテゴリ（業種など）

### script_folders テーブル
- 階層構造のフォルダ（メイン台本/アウト返し）

### script_items テーブル
- 実際のトーク内容（戦略メモ・次の一手付き）

詳細は `src/lib/db/schema.sql` を参照してください。

## アーキテクチャ

### 🎯 「誰でもトップアポインターになれる」仕組み

1. **データ収集**: 新人の課題音声 + マネージャーの指導音声
2. **文字起こし**: Whisper APIで両方を自動テキスト化
3. **AI分析**: Gemini 1.5 Proが「正解の論理」を抽出
4. **ナレッジ化**: 再現可能なノウハウとしてDB保存
5. **スクリプト化**: AI提案をビジュアルエディタで承認・反映
6. **属性最適化**: 顧客属性に応じて最適なトークを自動選択
7. **実行**: Live Assistantで通話中にリアルタイム支援
8. **ログ蓄積**: 実行結果を分析して更なる改善へ

### 🔄 フィードバックループ

```
課題音声 → 指導音声 → AI分析 → スクリプト提案
    ↓                                  ↓
実行ログ ← Live Assistant ← ビジュアル編集 ← 承認
    ↓                                  ↑
新たな課題発見 ─────────────────────────┘
```

この循環により、組織全体のトーク品質が継続的に向上します。

## 🛡️ Phase 5: 現場で使える実戦機能

### 1. カテゴライズド・コマンドパネル（お守りパネル）

**画面右側に常駐する切り返し集:**

通話中に困ったとき、すぐに使える「お守り」として機能します。

**4つのカテゴリ:**
- 🛡️ **断り文句**: 「忙しい」「必要ない」への切り返し
- ❓ **質問集**: 業種確認、意思決定者確認など
- 🎯 **ヒアリング項目**: 現状把握、予算感確認など
- 💎 **さしどころトーク**: 差別化トーク、導入事例など

**特徴:**
- カテゴリをクリックすると、登録されたナレッジが表示
- 各ナレッジには「戦略メモ」と「次の一手」が付属
- 使用回数と成功率を自動集計
- クリックでカンペ画面に即座に表示

**使い方:**
1. スクリプト実行中、右側のパネルでカテゴリを選択
2. 該当するトークをクリック
3. メイン画面に「お守りトーク」として表示
4. そのまま読み上げて対応

### 2. トップアポインターの戦略メモ

**各ノードに「なぜこのトークが効くのか」を表示:**

- 💡 **戦略メモ**: トップの思考・意図を学べる
- ➡️ **次の一手**: 勝ちパターンへの最短ルート
- 📊 **成功要因**: アポ獲得につながる要素

**例:**
```
トーク: 「1分だけお時間をいただけませんか？」

💡 戦略メモ:
具体的な時間を提示することで心理的ハードルを下げる。
また、「切っていただいて構いません」と逃げ道を作ることで、
聞く姿勢を引き出す。

➡️ 次の一手:
1分経過後、「実は〇〇という課題をお持ちではありませんか？」
と具体的な課題提起に移行する。
```

### 5. knowledge_baseテーブル

**静的なトーク集と動的な分析結果の統合:**

```sql
CREATE TABLE knowledge_base (
  id TEXT PRIMARY KEY,
  category TEXT NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  tags TEXT,
  logic_explanation TEXT,      -- さしどころトークロジック
  success_factors TEXT,         -- アポ獲得要因
  next_move_hint TEXT,          -- 次の一手
  usage_count INTEGER,          -- 使用回数
  success_count INTEGER,        -- 成功回数
  created_at INTEGER,
  updated_at INTEGER
);
```

**活用シーン:**
1. 通話前: ナレッジベースで予習
2. 通話中: コマンドパネルで即座に参照
3. 通話後: 使用したトークの成功率を記録
4. 分析: どのトークが効果的かデータで把握

## 📁 Phase 6: IDE + Notion型 階層構造ワークスペース（V2: タブ切り替え＆カスタマイズ対応）

ReactFlowのツリー型UIを凍結し、現場のアポインターが最も直感的に操作できる新しいワークスペースを構築。

### V2での主な改善点

1. **複数の基本トークに対応**: 1つのメイン台本だけでなく、状況に応じた複数の台本をタブで切り替え可能
2. **武器庫のカスタマイズ**: アポインターごとに必要なジャンルだけを表示できる（例: 新人は「断り文句」のみ、ベテランは全部表示）
3. **モーダルUI**: 右ペインのアイテムをクリックすると、中央にフワッとオーバーレイ表示され、トークの流れを遮らない
4. **ジャンル無制限**: ユーザーが自由にジャンルを作成し、独自の武器庫を構築可能
5. **データ構造の柔軟化**: `folder_type` を `base_talk` / `situational` に変更し、`is_visible_in_sidebar` で表示制御

### コンセプト

**「業種カテゴリ > フォルダ(タブ切り替え) > トークアイテム」の3階層:**

```
📁 IT企業（カテゴリ選択）
  ├── 📄 新規架電用 (base_talk) ← 中央ペインのタブ
  │   ├── 📝 挨拶と自己紹介
  │   └── 📝 時間確認
  ├── 📄 再架電用 (base_talk) ← 中央ペインのタブ
  │   └── 📝 再架電の挨拶
  ├── 🛡️ 断り文句 (situational) ← 右ペインの武器庫（表示/非表示カスタマイズ可）
  │   ├── 📝 「忙しい」への切り返し
  │   └── 📝 「必要ない」への切り返し
  └── 🛡️ 興味あり系 (situational) ← 右ペインの武器庫
      └── 📝 無料デモの提案

📁 建設業（カテゴリ選択）
  └── 📄 標準台本 (base_talk)
      └── 📝 人手不足課題の提起
```

### 1. データベース構造

**3つの新しいテーブル:**

```sql
-- 大カテゴリ（業種など）
CREATE TABLE script_categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  created_at INTEGER
);

-- フォルダ（基本トーク/状況別）
CREATE TABLE script_folders (
  id TEXT PRIMARY KEY,
  category_id TEXT NOT NULL,
  name TEXT NOT NULL,
  folder_type TEXT NOT NULL,  -- 'base_talk' (中央タブ) or 'situational' (右武器庫)
  is_visible_in_sidebar INTEGER DEFAULT 1,  -- 1=表示, 0=非表示
  sort_order INTEGER,
  created_at INTEGER,
  FOREIGN KEY (category_id) REFERENCES script_categories(id)
);

-- トークアイテム（実際の内容）
CREATE TABLE script_items (
  id TEXT PRIMARY KEY,
  folder_id TEXT NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  strategy_note TEXT,
  next_move_hint TEXT,
  sort_order INTEGER,
  created_at INTEGER,
  updated_at INTEGER,
  FOREIGN KEY (folder_id) REFERENCES script_folders(id)
);
```

✅ マイグレーション完了

### 2. 中央ペイン: タブ切り替え式の基本トーク

**中央エリア（メインの台本表示）:**
- 📑 基本トーク（`base_talk`）のフォルダをタブで表示（例: 新規架電用、再架電用、ネット充実企業用）
- ➕ 「基本トークを追加」ボタンで新しいパターンを作成
- 📄 選択したタブのトークアイテムを縦スクロールで表示
- ✏️ 各アイテムをクリックして詳細表示、編集ボタンでモーダル編集
- 💡 戦略メモ表示（紫色のボックス）
- ➡️ 次の一手表示（緑色のボックス）

### 3. 右ペイン: カスタマイズ可能な武器庫

**右側パネル（状況別トーク）:**
- 🛡️ 状況別（`situational`）のフォルダをアコーディオン表示
- ⚙️ 「カスタマイズ」ボタンで表示/非表示を切り替え
- 📝 各フォルダを展開してトークアイテムを表示
- クリックすると中央にフワッとモーダル表示（トークの流れを遮らない）
- ➕ 「ジャンルを追加」ボタンで無制限にジャンルを作成可能

### 4. 直感的なCRUD操作

**作成:**
- カテゴリ: ヘッダーのドロップダウンから選択（新規作成は今後実装予定）
- 基本トーク: 「＋ 基本トークを追加」ボタン（中央ペイン）
- 状況別ジャンル: 「➕ ジャンルを追加」ボタン（右ペイン）
- トークアイテム: 各フォルダの「＋ トークを追加」ボタン
- すべてプロンプトで名前・内容を入力

**読み込み:**
- カテゴリをドロップダウンで切り替え
- タブをクリックして基本トークを切り替え
- アコーディオンを展開して状況別トークを表示
- アイテムをクリックして詳細表示（中央: そのまま表示、右: モーダル表示）

**更新:**
- アイテムを選択して「✏️ 編集」
- モーダルでタイトル・内容・戦略メモ・次の一手を修正
- 「💾 保存」で更新

**表示カスタマイズ:**
- 右ペイン上部の「⚙️ カスタマイズ」をクリック
- 表示したいジャンルをチェックボックスで選択
- 選択したジャンルのみが右ペインに表示される

**削除:**
- アイテムを選択して「🗑️ 削除」
- 確認ダイアログで承認

## 📞 Phase 8: ライブ・コーチング（実戦コックピット）

**「トップアポインターが横で伴走して助言をくれる」UXを完全再現。**

アポインターが通話中に「現在の状況」をリアルタイムでシステムにインプットすると、それに応じて**今投げるべき質問・トーク**が自動で展開されるライブ・コーチングUIを実装しました。

### コンセプト

「話を聞いてくれてる（ポチッ）」→ 画面にスッと「じゃあ、現状の課題についてこの質問を投げてみて！」とトークが出現。

これは、新人アポインターが現場で**トップアポインターから直接アドバイスを受けている**ような体験を実現します。

### 1. データベース構造

**2つの新しいテーブル:**

```sql
-- 状況タグ（「話を聞いてくれる」「HPが古い」など）
CREATE TABLE situation_tags (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  category TEXT NOT NULL, -- '相手の反応', 'Web状況', '属性'
  description TEXT,
  sort_order INTEGER,
  created_at INTEGER
);

-- トークアイテムと状況タグの紐付け
CREATE TABLE item_situations (
  id TEXT PRIMARY KEY,
  item_id TEXT NOT NULL,
  situation_tag_id TEXT NOT NULL,
  priority INTEGER DEFAULT 0,
  created_at INTEGER,
  FOREIGN KEY (item_id) REFERENCES script_items(id),
  FOREIGN KEY (situation_tag_id) REFERENCES situation_tags(id)
);
```

### 2. 状況インプット・パネル（画面上部）

- 📌 **カテゴリ別タグ**: 「相手の反応」「Web状況」「属性」
- 🔘 **トグル式**: クリックで選択/解除
- 📊 **選択数表示**: リアルタイム表示
- ✨ **視覚的フィードバック**: 選択中はブルーでハイライト

### 3. ライブ・コーチング・タイムライン（中央）

- 📄 **基本トーク**: 全員共通の台本
- 🎯 **トップからの助言**: 状況に応じて自動提案
- 💡 **トップの狙い**: 戦略メモを表示
- 📊 **マッチ度スコア**: 選択した状況との関連度

### 4. クイック・レスポンス（右ペイン）

- 🛡️ **武器庫**: 断り文句への返しを常駐
- 📦 **アコーディオン**: 必要な時だけ展開
- 🔍 **モーダル表示**: トークの流れを遮らない

### 5. 使い方

**初回:**

**実戦:**

2. 自動で提案される助言トークを読み上げ

### 6. サンプル状況タグ

- **相手の反応**: 話を聞いてくれる、忙しそう、警戒している、質問してくる
- **Web状況**: HPなし、HPが古い、SNSのみ、広告出稿中
- **属性**: 代表の写真あり、声が若い、創業5年以内、従業員10名以下
