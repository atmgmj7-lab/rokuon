# Rokuon - 録音アプリケーション

Next.js 14+ (App Router)、TypeScript、Tailwind CSS、Turso を使用した録音アプリケーションです。

## セットアップ

### 1. 依存関係のインストール

```bash
npm install
```

### 2. 環境変数の設定

`.env` ファイルに以下の環境変数を設定してください：

```env
TURSO_DATABASE_URL=libsql://your-database.turso.io
TURSO_AUTH_TOKEN=your-auth-token
OPENAI_API_KEY=sk-your-openai-api-key
GOOGLE_AI_API_KEY=your-google-ai-api-key
```

#### Tursoデータベースの作成方法

1. [Turso](https://turso.tech/) にアカウントを作成
2. Turso CLIをインストール:
   ```bash
   brew install tursodatabase/tap/turso
   ```
3. ログイン:
   ```bash
   turso auth login
   ```
4. データベースを作成:
   ```bash
   turso db create rokuon
   ```
5. データベースURLを取得:
   ```bash
   turso db show rokuon --url
   ```
6. 認証トークンを取得:
   ```bash
   turso db tokens create rokuon
   ```

### 3. データベースマイグレーション

環境変数を設定した後、以下のコマンドでデータベーステーブルを作成します：

```bash
npm run migrate
```

### 4. 開発サーバーの起動

```bash
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開いてください。

## 機能

### 🎙️ Phase 1: テレアポ音声アップロード & 文字起こし

1. ホームページにアクセスすると、音声アップロードフォームが表示されます
2. タイトルと説明（任意）を入力し、音声ファイルを選択します
3. 「📤 アップロードして文字起こし」ボタンをクリックします
4. OpenAI Whisper APIが音声を解析し、自動的に文字起こしを行います（数十秒かかります）
5. 文字起こし結果がその場で表示され、データベースに保存されます

**特徴:**
- テレアポに最適化されたプロンプト（フィラー「えー、あのー」を残して正確に書き起こし）
- リアルタイムのローディング状態表示
- ファイルサイズ、録音時間などのメタデータも自動保存
- Tursoデータベースに安全に保存

### 📞 Phase 2: インタラクティブなトークスクリプト（Talkz風UI）

アポインターが通話中に画面を見ながら、顧客の反応に合わせてトークを分岐させる機能。

1. ホームページから「📞 トークスクリプト」をクリック
2. スクリプト一覧ページで「➕ 新規スクリプトを作成」
3. サンプルスクリプトを作成して実行
4. 通話中に顧客の反応に応じて選択肢をクリック
5. 自動的に次のトークが表示される

**特徴:**
- 分岐型トークスクリプト（顧客の反応に応じて自動分岐）
- 会話履歴の表示（どの経路を辿ったか確認可能）
- 戻る機能（前の選択に戻れる）
- リセット機能（最初からやり直せる）
- サンプルスクリプト付き（CRM営業のトークフロー）
- Talkz風の洗練されたUI

**使い方:**
1. 通話前にスクリプトを開く
2. 通話しながら画面を見てトークを読む
3. 顧客の反応に応じて選択肢をタップ
4. 次に言うべきことが自動表示される

### 📊 実行ログ機能（自動保存）

スクリプトの実行履歴を自動的にデータベースに保存し、分析できる機能。

**自動記録される情報:**
- どのルートを通ったか（ノードIDの配列）
- 最終的な結果（アポ獲得、断られた、資料送付など）
- 実行日時

**ログの閲覧:**
1. スクリプト一覧で「📊」ボタンをクリック
2. 実行ログページで統計情報を確認
   - 総実行回数
   - アポ獲得数
   - 断られた数
3. 各実行の詳細な分岐ルートを確認

**活用方法:**
- どの分岐パターンが成約につながりやすいかを分析
- 断られやすいポイントを特定してスクリプトを改善
- チーム全体のトーク品質を可視化

### 🤖 Phase 3: 音声・指導ペアのマルチモーダル分析（Gemini 1.5 Pro）

「誰でもトップアポインターになれる」ための核心機能。課題音声と指導音声をペアで分析し、再現可能なノウハウを抽出。

**機能:**
1. **課題音声のアップロード**
   - 新人のテレアポ音声をアップロード
   - 自動的にWhisperで文字起こし

2. **指導音声の紐付け**
   - 課題音声に対して、マネージャーの指導音声を追加
   - 親子関係でデータベースに保存
   - 指導音声も自動で文字起こし

3. **AI分析（Gemini 1.5 Pro）**
   - 課題音声と指導音声を比較分析
   - 上司が指摘している「正解の論理」を抽出
   - 業種・状況タグを自動付与
   - 学習用ナレッジとして構造化

**分析結果に含まれる情報:**
- 📊 分析サマリー
- ❌ 問題点（新人の課題）
- ✅ 正解アプローチ（上司の指摘）
- 🧠 理由・根拠（なぜそれが正解か）
- 🏷️ タグ（業種、顧客反応、トークフェーズ）
- 💡 学習用ナレッジ（再現可能なノウハウ）
- 📝 スクリプト提案（次回のトーク改善案）

**使い方:**
1. 「📼 録音一覧」から課題音声を確認
2. 「➕ 指導音声を追加」をクリック
3. マネージャーの指導音声をアップロード
4. 「🤖 AI分析」ボタンでGeminiが自動分析
5. 抽出されたナレッジを今後のトレーニングに活用

### 🎨 Phase 4: ビジュアル・スクリプト・エディタと思考同期型カンペUI

トップアポインターの「思考のツリー」を可視化し、顧客属性に応じて動的にトークを出し分ける革新的なシステム。

#### 1. ビジュアル・スクリプト・エディタ

**ReactFlowを使用したドラッグ&ドロップエディタ:**
- 📊 スクリプトの分岐構造を視覚的に編集
- 🔗 ノード同士をドラッグで接続
- 📝 各ノードの詳細をサイドパネルで確認・編集
- 💾 変更をワンクリックで保存
- 🗺️ ミニマップで全体構造を把握

**使い方:**
1. スクリプト一覧で「✏️」ボタンをクリック
2. ビジュアルエディタでノードを配置
3. ノードをクリックして詳細を確認
4. 「💾 保存」で変更を反映

#### 2. 思考同期型 Live Assistant

**プレ・コール調査システム:**

通話前に顧客の属性を選択すると、最適なトークが自動的に表示される革新的なUI。

**属性タグ:**
- 🌐 **Web状況**: HPなし / SNSのみ / 広告あり
- 👔 **求人状況**: 募集中 / なし
- 🎯 **ターゲット**: 社長 / 担当者

**仕組み:**
1. 各開始ノードに `hypothesis_tags` を設定
2. アポインターがタグを選択
3. AIがマッチングスコアを計算
4. 最適なスタートノードを自動選択
5. そのノードから通話を開始

**使い方:**
1. スクリプト一覧で「🎯 Live Assistant」をクリック
2. プレ・コール調査パネルで顧客属性を選択
3. 最適なトークが自動的にハイライト
4. 「📞 このトークで通話を開始」をクリック

#### 3. AI提案の承認・反映フロー

**分析結果からスクリプトへの自動提案:**

Gemini分析で抽出された「新しい切り返し案」を、ワンクリックでスクリプトに追加。

**フロー:**
1. 📊 AI分析を実行
2. 🤖 「新しい切り返し案」を提案として生成
3. ✏️ スクリプト編集ページの「AI提案」タブで確認
4. ✅ 「承認して追加」でビジュアルエディタに反映
5. 🎨 エディタで位置を調整して保存

**特徴:**
- 分析結果を手動で転記する必要なし
- 提案内容を詳細に確認してから承認
- 却下した提案は記録されない
- 人間の判断を尊重した半自動化

## データベーススキーマ

### recordings テーブル
- 録音データのメタデータを保存
- `recording_type`: 'case' (課題音声), 'model' (お手本), 'feedback' (指導音声)
- `parent_id`: 指導音声の場合、課題音声のIDを参照
- `category_id`: 業種・属性等の区分

### users テーブル
- ユーザー情報を保存（将来的な拡張用）

### transcripts テーブル
- 録音の文字起こしデータを保存

### scripts テーブル
- トークスクリプトと分岐ロジックをJSON形式で保存

### script_logs テーブル
- スクリプト実行ログ（通過した分岐ルート、結果ステータス）を保存

### analysis_results テーブル
- Gemini 1.5 Proによる分析結果を保存
- 課題音声と指導音声のペア分析
- 抽出されたタグ、学習用ナレッジ

### knowledge_base テーブル
- 静的なトーク集・戦略メモ
- カテゴリ、ロジック説明、成功要因、次の一手

### script_categories テーブル
- 階層構造の大カテゴリ（業種など）

### script_folders テーブル
- 階層構造のフォルダ（メイン台本/アウト返し）

### script_items テーブル
- 実際のトーク内容（戦略メモ・次の一手付き）

詳細は `src/lib/db/schema.sql` を参照してください。

## アーキテクチャ

### 🎯 「誰でもトップアポインターになれる」仕組み

1. **データ収集**: 新人の課題音声 + マネージャーの指導音声
2. **文字起こし**: Whisper APIで両方を自動テキスト化
3. **AI分析**: Gemini 1.5 Proが「正解の論理」を抽出
4. **ナレッジ化**: 再現可能なノウハウとしてDB保存
5. **スクリプト化**: AI提案をビジュアルエディタで承認・反映
6. **属性最適化**: 顧客属性に応じて最適なトークを自動選択
7. **実行**: Live Assistantで通話中にリアルタイム支援
8. **ログ蓄積**: 実行結果を分析して更なる改善へ

### 🔄 フィードバックループ

```
課題音声 → 指導音声 → AI分析 → スクリプト提案
    ↓                                  ↓
実行ログ ← Live Assistant ← ビジュアル編集 ← 承認
    ↓                                  ↑
新たな課題発見 ─────────────────────────┘
```

この循環により、組織全体のトーク品質が継続的に向上します。

## 🛡️ Phase 5: 現場で使える実戦機能

### 1. カテゴライズド・コマンドパネル（お守りパネル）

**画面右側に常駐する切り返し集:**

通話中に困ったとき、すぐに使える「お守り」として機能します。

**4つのカテゴリ:**
- 🛡️ **断り文句**: 「忙しい」「必要ない」への切り返し
- ❓ **質問集**: 業種確認、意思決定者確認など
- 🎯 **ヒアリング項目**: 現状把握、予算感確認など
- 💎 **さしどころトーク**: 差別化トーク、導入事例など

**特徴:**
- カテゴリをクリックすると、登録されたナレッジが表示
- 各ナレッジには「戦略メモ」と「次の一手」が付属
- 使用回数と成功率を自動集計
- クリックでカンペ画面に即座に表示

**使い方:**
1. スクリプト実行中、右側のパネルでカテゴリを選択
2. 該当するトークをクリック
3. メイン画面に「お守りトーク」として表示
4. そのまま読み上げて対応

### 2. トップアポインターの戦略メモ

**各ノードに「なぜこのトークが効くのか」を表示:**

- 💡 **戦略メモ**: トップの思考・意図を学べる
- ➡️ **次の一手**: 勝ちパターンへの最短ルート
- 📊 **成功要因**: アポ獲得につながる要素

**例:**
```
トーク: 「1分だけお時間をいただけませんか？」

💡 戦略メモ:
具体的な時間を提示することで心理的ハードルを下げる。
また、「切っていただいて構いません」と逃げ道を作ることで、
聞く姿勢を引き出す。

➡️ 次の一手:
1分経過後、「実は〇〇という課題をお持ちではありませんか？」
と具体的な課題提起に移行する。
```

### 5. knowledge_baseテーブル

**静的なトーク集と動的な分析結果の統合:**

```sql
CREATE TABLE knowledge_base (
  id TEXT PRIMARY KEY,
  category TEXT NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  tags TEXT,
  logic_explanation TEXT,      -- さしどころトークロジック
  success_factors TEXT,         -- アポ獲得要因
  next_move_hint TEXT,          -- 次の一手
  usage_count INTEGER,          -- 使用回数
  success_count INTEGER,        -- 成功回数
  created_at INTEGER,
  updated_at INTEGER
);
```

**活用シーン:**
1. 通話前: ナレッジベースで予習
2. 通話中: コマンドパネルで即座に参照
3. 通話後: 使用したトークの成功率を記録
4. 分析: どのトークが効果的かデータで把握

## 📁 Phase 6: IDE + Notion型 階層構造ワークスペース（V2: タブ切り替え＆カスタマイズ対応）

ReactFlowのツリー型UIを凍結し、現場のアポインターが最も直感的に操作できる新しいワークスペースを構築。

### V2での主な改善点

1. **複数の基本トークに対応**: 1つのメイン台本だけでなく、状況に応じた複数の台本をタブで切り替え可能
2. **武器庫のカスタマイズ**: アポインターごとに必要なジャンルだけを表示できる（例: 新人は「断り文句」のみ、ベテランは全部表示）
3. **モーダルUI**: 右ペインのアイテムをクリックすると、中央にフワッとオーバーレイ表示され、トークの流れを遮らない
4. **ジャンル無制限**: ユーザーが自由にジャンルを作成し、独自の武器庫を構築可能
5. **データ構造の柔軟化**: `folder_type` を `base_talk` / `situational` に変更し、`is_visible_in_sidebar` で表示制御

### コンセプト
